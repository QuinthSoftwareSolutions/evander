## Scope and method

- Python scope follows `pyproject.toml` (`tests/` and pytest naming conventions). Admin Web scope follows the `test:unit`, `test:browser`, and `test:smoke` globs in `frontend/admin-web/package.json`.
- Every ledger row records KEEP or REMOVE and a short rationale. This third pass revisited documentation text checks, source-token tests, fixture-only assertions, value echoes, and shallow duplicates. The 280 REMOVE decisions were applied on `feature/prune-unjustified-tests`.
- Tests with distinct security, isolation, operational, schema, and user-facing behavior contracts remain KEEP. The review was source-based and read-only; the removal followed afterward. No test suite was run for the removal, so this report makes no pass/fail claim.

## Principles for future tests

- Name the plausible regression and the product behavior the test would catch. If neither is clear, omit the test.
- Exercise behavior through the narrowest stable public boundary. Inspect source text only when the source artifact itself is the contract, such as a deployable script or package manifest.
- Keep one strongest test for a behavior. When a later integration or browser test covers the same path better, delete the weaker duplicate.
- Derive expectations independently of the fixture. Reading back values supplied by the test, or asserting a hand-authored example against itself, gives little regression signal.
- Spend test budget on meaningful failure modes: authorization, scope isolation, persistence, retries, recovery, and externally visible output.
- For editor and API schemas, assert the fields, defaults, and validation rules users depend on. Avoid pinning wording, CSS selectors, implementation placement, or empty field lists without a demonstrated contract.
- Validate documentation with link and publication checks where useful. A keyword in prose does not establish that an instruction is correct.
- Reassess a test when the production path changes or stronger coverage is added. Remove tests of dead code, fixtures alone, and historical implementation choices.
